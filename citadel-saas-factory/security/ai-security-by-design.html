3. Triple-Layer Guardrails

Layer 1: Guardrails AI (output validation)

  • hub://guardrails/hallucination_free - fabricated fact detection
  • hub://guardrails/provenance_llm - RAG grounding verification
  • hub://guardrails/toxic_language - toxic content filter (threshold 0.5)
  • hub://guardrails/detect_pii - PII masking (email, phone, SSN)

Layer 2: Input Sanitization (pre-model)

  • 16 regex patterns blocking instruction hijacking, tool triggers, and secrets leakage
  • Applied to: RAG document content, browser tab content, external API responses
  • Truncation: 16KB for RAG docs, 8KB for browser content
  • Redaction: patterns replaced with [FILTERED] or [REDACTED]

Layer 3: Output Action Enforcement (post-model)

  • Allowlist: search, retrieve, summarize, analyze, compare, explain, recommend, list, draft, review
  • Any output attempting to trigger actions outside this list is blocked
  • Hallucination threshold: 0.85 (outputs below trigger retry, max 3 attempts, then reject)
  • Fail-closed: if guardrails library is unavailable, outputs are rejected by default

4. RAG Security

RAG documents are the primary indirect prompt injection vector. Every document ingested into the vector store passes through sanitize_rag_context() before being used as generation context.

Ingestion Security

  • All document content treated as untrusted regardless of source
  • Chunker strips tool-trigger patterns before embedding
  • Metadata provenance: every chunk records its source, ingest timestamp, and version
  • GIN index on metadata enables rapid audit queries by source or time range

Retrieval Security

  • Domain-scoped retrieval: agents only retrieve chunks tagged with their domain
  • Relevance grading prevents low-quality (potentially adversarial) chunks from reaching generation
  • Citation requirement: answer must cite chunk IDs, enabling post-hoc verification
  • Self-check loop verifies all claims map to retrieved spans

5. Browse Agent Security

The Chrome extension captures active tab content on explicit user action only. No background surveillance, no cross-tab access, no automatic transmission.

Content Processing Pipeline

StepActionPurpose
1User clicks extension iconExplicit consent gate
2Capture document.body.innerText (max 10KB)Text only, no DOM/scripts
3sanitize_tab_content()Strip 16 injection patterns
4Truncate to 8KBLimit blast radius
5Model generationConstrained to summarize/explain actions
6Guardrails validationOutput safety check

Permissions Model

  • activeTab - only the tab the user explicitly activated
  • sidePanel - UI surface for interaction
  • storage - local preference storage only
  • No tabs, no history, no webRequest, no cookies
  • Host permission limited to http://localhost:8000/* (backend only)

6. Policies

OPA Policy: Browse Endpoint Rate Limiting

package citadel.browse

default allow = false

allow {
    input.method == "POST"
    input.path == "/agent/browse"
    count(input.requests_last_minute) < 10
    input.content_length < 20000
}

deny[msg] {
    input.content_length >= 20000
    msg := "Tab content exceeds maximum size (20KB)"
}

deny[msg] {
    count(input.requests_last_minute) >= 10
    msg := "Rate limit exceeded: max 10 browse requests per minute"
}

Kyverno Policy: Agent Container Restrictions

apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: citadel-agent-restrictions
spec:
  rules:
  - name: limit-agent-resources
    match:
      resources:
        kinds: [Pod]
        namespaceSelector:
          matchLabels:
            app.kubernetes.io/part-of: citadel
    validate:
      message: "Agent pods must have resource limits"
      pattern:
        spec:
          containers:
          - resources:
              limits:
                memory: "?*"
                cpu: "?*"
  - name: deny-privileged
    match:
      resources:
        kinds: [Pod]
    validate:
      message: "Agent pods must not run privileged"
      pattern:
        spec:
          containers:
          - securityContext:
              privileged: false
