# Validation Report: `agents-office-implementation.plan.md` vs. current repo state

## Headline finding (breaks almost everything downstream)

The plan's claim that current department names and count are "`exec`, `revenue`, `engineering`, `frontend`, `devops`, `fin`, `success`, `product`" (line 12) is **false**. The repo's actual current department keys, confirmed independently in three places, are:

```
exec, revenue, engineering, frontend, devops, secdata, fin, content
```

- `backend/app/mcp.py:16`: `DEPT_KEYS = ["exec", "revenue", "engineering", "frontend", "devops", "secdata", "fin", "content"]`
- `office.agents.json` seat counts by department: `revenue:8, engineering:6, devops:5, frontend:4, content:3, secdata:3, exec:3, fin:3` (35 total)
- `src/data.js`'s `LAYOUT` and `BILLBOARDS` objects (lines 80-105): keyed `exec, revenue, engineering, frontend, devops, secdata, fin, content` — no `success` or `product` key exists anywhere in the frontend.

There is no department called `success` or `product` anywhere in the current code. The plan uses `success`/`product` as if they already exist (Part II's target-cap table, Task 11's "pilot department is `success`", Task 2's connector matrix). It repeatedly refers to "the same old→new mapping used elsewhere in this plan" (Task 6b) or says to "re-derive their current department... e.g. an agent that was `sales` is now `revenue`" (Task 6) — but **no such old→new mapping table exists anywhere in the document.** I read the full plan text; it is not there.

This single gap is why Task 11's pilot target, Task 6/6b's remap instructions, and the Org Redesign target table are all currently non-executable: someone must first decide whether `content` or `secdata` becomes `success` (and which becomes `product`), and that decision is not in the plan. This does not reopen the already-decided 35→70 scope question — it is a missing mapping artifact the plan's own tasks assume exists.

Compounding this, `.claude/CLAUDE.md` (checked into the repo) describes a *third*, older taxonomy: 6 departments (`emails`, `sales`, `marketing`, `ops`, `fin`, `delivery`), 35 seats, caps 5/6/7/6/4/7. This matches neither the plan's 8-dept scheme nor the repo's actual 8-dept scheme. Three different department vocabularies are now live across the project's own guidance documents; the plan never acknowledges the CLAUDE.md mismatch. (This is the same fact established above by file:line evidence — noted here once, not re-litigated below.)

## Overall verdict

**Not a reliable basis to start executing Task 1 onward right now, without corrections.** The majority of the document's file/line/code claims — the engine, config, dependency, and most of the API-contract and layout-math claims — are genuinely accurate and carefully checked. But the following need fixing before execution starts:

1. **The department-naming mismatch (load-bearing).** The plan's "current" department set (`exec, revenue, engineering, frontend, devops, fin, success, product`) does not match the repo's actual current set (`exec, revenue, engineering, frontend, devops, secdata, fin, content`) in `office.agents.json`, `mcp.py:16`, and `src/data.js`'s `LAYOUT`/`BILLBOARDS`. Every task assuming `success`/`product` exist today (Task 2's connector matrix, Task 11's pilot target, the 70-seat target table, Tasks 6/6b's remap instructions) needs an explicit old→new mapping table added right after line 12, before any of those tasks can be executed.
2. **The `/api/chat` contract row is factually wrong, not just stale.** Fix the plan's documented response shape to `{"reply": string}` (confirmed from `main.py:423-451`), and fix the `main.py:454-456` description from "404 catch-all" to "generic exception handler → 500" (confirmed from the actual decorator).
3. **The `npm run check` baseline is wrong.** Correct "37/38, one unrelated failure" to the actual current result: **33/38**, five failures (the four interactive smoke-test failures listed in §2, plus the one `/api/brain` failure the plan already accounts for).
4. **Files-to-Change table self-contradiction.** Change `backend/tests/test_api_contract.py`'s marking from `CREATE` to `UPDATE` — the plan's own ground-truth section already confirms the file exists.

Secondary correction: fix Task 6b's framing — the `secdata`/`content` keys in `office.config.local.json` are the *real current* department names, not a pre-redesign artifact, until the rename mapping above is settled.

None of this reopens the already-decided scope question (35→70 seats) or the Foundation engine work, which the task explicitly places out of bounds to re-litigate — these are corrections to the plan's stated facts about the repo and to one internal self-contradiction, not to its goals.
