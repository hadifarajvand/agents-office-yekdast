Consequence: `office.config.local.json`'s `mcp.departments` keys (`github/gitlab/slack/gmail/notion/docker/prometheus/grafana` → department lists using `content`, `secdata`, `revenue`, `engineering`, `frontend`, `devops`, `fin`, `exec`) are **not stale** — they match the live roster/layout exactly, key for key. That is false: the names are changing (`secdata`→? , `content`→?, or `secdata`/`content` are being retired in favor of new `success`/`product` departments). The plan never says this rename is happening and never reconciles it — it simply asserts both "current departments are already exec/revenue/engineering/frontend/devops/fin/success/product" (false) and "the target keeps the same 8 departments" (internally consistent with the false premise, but not with reality).

**This is not a cosmetic naming quibble**: Task 2's runtime policy gate and Task 6b's "fail loudly on an unrecognized key" assertion both depend on knowing the real department key set. Implementing Task 6b as literally written would make `office.config.local.json` reference non-existent departments and break the live connector-policy wiring for `secdata` and `content` — the opposite of its stated goal.
