## Headline finding — the plan's central factual premise is wrong

The plan states, as a load-bearing, repeated fact (lines 12, 20, 22, 24, 234–246, 300, Task 2's connector matrix, Task 6b, Task 11): that the current 8 departments are **`exec, revenue, engineering, frontend, devops, fin, success, product`**, and that `office.config.local.json`'s `mcp.departments` keys (`content`, `secdata`) are *stale, pre-redesign* names that need remapping to `success`/`product`.

There is no `success` or `product` department anywhere in this file.
- `src/data.js:17`: `export const DEPT_KEYS = ['exec', 'revenue', 'engineering', 'frontend', 'devops', 'secdata', 'fin', 'content'];` — the frontend's own canonical list, same 8 keys, no `success`/`product`.
- `src/data.js:80-89` (`LAYOUT`): same 8 keys (`exec, revenue, engineering, frontend, devops, secdata, fin, content`), each with real `pos/w/d` isometric placement data.
- `backend/app/mcp.py:16`: `DEPT_KEYS = ["exec", "revenue", "engineering", "frontend", "devops", "secdata", "fin", "content"]` — same 8 keys, hardcoded in the backend's own policy module.
- A repo-wide grep for `"success"` / `"product"` as department identifiers across every `.json`/`.js`/`.py` file (outside the plan document itself and the `.arena` scratch folder) returns **zero matches**.
- `office.config.local.json`'s `mcp.departments` keys (`engineering, frontend, devops, revenue, secdata, slack: …content…, gmail: content/revenue, notion: …secdata…`) are **not stale** — they are keyed to exactly the department ids that exist today in `office.agents.json`, `src/data.js`, and `mcp.py`. The plan's Task 6b ("fix the stale keys, remap `content`→`success`, `secdata`→`product`-or-whatever") would *introduce* breakage into a file that currently matches the roster correctly.

So: Part I's "Current agent stack — ground truth" section (lines 18-24), Task 6b in its entirety, and the whole of Part II's department table (lines 234-246), Citadel mapping section, and Task 11's pilot-department choice (`success`) are built on a department-naming scheme that does not exist in this repository. This isn't a stale-doc nit — it invalidates the specific remediation Task 6b proposes and the specific pilot target Task 11 names.
